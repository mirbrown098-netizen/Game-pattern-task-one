For Task 3, I integrated all six design patterns into one project and moved the architecture into Unity’s 3D Starter Assets. The main classes I worked with were Game Manager, Audio Manager, Command Handler, PlayerStateMachine, EnemyStateMachine, Enemy Factory, and Pooled Enemy. One important decision was routing the Starter Assets controls through Command Handler. I created commands for movement, camera look, jumping, sprinting, attacking, enemy spawning, recycling, and game-state changes. This allowed me to keep the Starter Assets character controller while still following the Command pattern.
Another challenge was moving the enemy system from the earlier 2D scene into the 3D environment. I used EnemyStateMachine to control the zombie’s Idle, Chase, and Attack states, with Vector3.MoveTowards handling its chase movement. I also connected EnemyFactory to the Zombie3DData ScriptableObject so zombies could be created through the Factory pattern and recycled through the Object Pool instead of constantly creating and destroying objects.
I also used the Observer pattern to keep systems separated. PlayerStateMachine and EnemyStateMachine fire state-change events, while StateObserver and Audio Manager listen for those events. For example, attacking causes Audio Manager to respond to the player-state event and play a sound rather than the attack code directly playing an AudioSource. Finally, I added a simple Main Menu and Game Over display so the Game Manager state transitions are visible during the demo. The biggest improvement from my previous task was making the patterns work together inside a more complete and playable 3D scene.
